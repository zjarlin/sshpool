# 跨物理机接入与无 RAID 存储

SSH 能连接、KVM 能创建 VM，只说明设备有资格进入实验。当前一个 Linux 客体的跨节点执行仍仅在同一 ESXi 的两台实验 VM 中验证，尚无跨物理机容量、性能或故障接管证据。

2026-11-06 已对另一台独立 x86 物理机做只读预检：Ubuntu 26.04.1、双路 Xeon E5-2620 v4、16 个物理核/32 个线程、约 60.5 GiB 内存。普通用户实际打开 KVM、查询 API 12 并创建和关闭空 VM 成功；嵌套虚拟化可用。未安装研究内核、未改宿主配置或磁盘。地址、账号、硬件清单原始记录保留在私有实验目录，不写入公开仓库。

## 时钟与隔离先于加入

该候选支持 `KVM_CAP_GET_TSC_KHZ`，不支持 `KVM_CAP_TSC_CONTROL`。现有 QEMU 候选要求执行节点使用相同的 TSC 频率；当前偏移校准不能解决不同频率的长期漂移。下一阶段先测各节点真实频率和 CPU 能力交集，再决定是否能使用共同频率或必须实现新的时间转换。不能去掉相等检查就宣称兼容。

实验应运行在专用、可回退的 Linux VM 中，限额覆盖 CPU、内存和磁盘占用，不把研究内核装到承载原有数据的物理宿主。记录 VM 与物理宿主的对应关系；同一机器上的多个 VM 仍只有一个物理故障域。

接入验收必须重做单节点对照，再运行同一客体、同一 PID 的跨宿主多线程内存校验。结合两台物理机的 KVM vCPU 线程与驻留页观测证明实际执行归属，并测单调时钟、长期漂移、定时器和网络异常。只有这些通过后，才考虑超过任一节点配额的驻留内存工作集；不能用 swap 或文件映射充当 DRAM 汇聚。

## 可以不用 RAID，但必须实现跨机冗余

Ceph 可以直接管理独立磁盘（通常一盘一个 OSD），无需先做硬件 RAID。CRUSH 的副本故障域应设置为物理主机；三副本通常需要至少三个独立存储主机，约三分之一原始容量可用，另需预留恢复余量。只有两个物理存储主机时，不能假装部署三台 VM 就得到三主机容错。仲裁、OSD 副本与允许写入的 `min_size` 是不同约束，应按实际故障模型设计。

SSI 负责 CPU、内存和设备的跨节点语义，Ceph 负责存储副本及故障恢复。二者需要集成，但不能互相替代：存储副本保住磁盘，不会自动恢复唯一存在于失效主机 RAM 中的客体状态。数据库还需要真实的 `fsync`、事务确认、崩溃恢复、写入隔离和 RPO/RTO 测试。

新盘加入前必须按序列号确认归属，检查分区、挂载、文件系统签名、LVM、md、ZFS 和已有业务使用情况。**检测不到文件系统不等于空盘。** 当前候选上有一块未挂载且文件系统类型未识别的已有分区；它不是可擦除授权，不用于实验。初期只用独立创建、配额受控的实验镜像文件；这些文件不能证明真实掉盘后的持久化可靠性。

Ceph 尚未部署。实现和验收拆在 [物理主机与存储场景](../features/190-ssi-physical-storage.feature)，整体仍受 [严格 SSI](../features/110-pooled-linux.feature) 与 [数据库恢复](../features/120-stateful-recovery.feature) 的门槛约束。
