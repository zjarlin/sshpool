# 架构和演进边界

控制面是一份 Rust 二进制。系统 OpenSSH 负责节点认证、HostKey、跳板和连接；TCP 透传层把客户端交给稳定 Linux 工作台的 OpenSSH。没有重写 SSH 协议，也没有为了统一入口改变原有设备路由。

## 一次构建

1. 项目必须有显式 `sshpool.toml`。客户端按路径稳定排序创建 tar，拒绝链接和常见凭据文件，并在写入前后比较文件清单以发现可见的并发修改。
2. 携带私有 token 和源码归档 SHA-256 上传到控制面。控制面限制上传数量、大小和时间，再次验证 tar 并独立重算摘要；不匹配时不发布任务。
3. 控制面对节点并行只读探测，在调度锁内检查平台、CPU、内存、磁盘、负载、运行配额和未确认清理的任务。
4. 选择节点后先持久化任务与容器唯一标识，再通过系统 OpenSSH 创建受限容器。镜像必须已存在且在节点允许清单内，架构必须一致，声明 `VOLUME` 的镜像被拒绝。容器创建后先按 `docker inspect` 的真实配置复核隔离与资源上限（`src/isolation.rs`），通过才 `docker start`；否则停在 `Created` 并删除。
5. 容器的 `/work` 和 `/tmp` 是有上限的 tmpfs，源码通过 stdin 导入；任务没有宿主目录挂载。根文件系统只读。`/work` 允许执行（编译产物要在里面运行），`/tmp` 禁止执行；两者都由创建后的真实配置复核。
6. 命令以非 root 身份执行；stdout/stderr 流回有大小上限的日志。超时或取消后核验标签并删除本任务容器。
7. 只收集声明的输出；控制面拒绝输出中的软硬链接、特殊文件和路径穿越。完整验证后发布产物。
8. 客户端在全新目录中提取产物；不会自动写回源工程。

## 故障语义

- 调度前资源不足：默认拒绝任务，保留每个候选节点的原因。任务可显式设置最长七天的持久等待期限和有限优先级；零等待保持原行为。
- 编译非零退出：失败，不重跑确定的编译错误。
- 基础设施错误/超时：只有任务明确幂等、禁网、配置重试、旧容器确认删除时才尝试下一节点。
- SSH 断线且清理无法确认：记录 `interrupted`，隔离该 Worker，拒绝进一步给它分配任务。隔离不要求重启控制面：`sshpool node reconcile [name]` 依据三类证据在线解除 —— 容器不存在、容器已停止，或 SSH 仍不可达但容器自带租约（`sleep 超时 + 180s`）已过期并留出 60 秒时钟偏差。证据写入 attempt 的 `cleanup_proof`；容器实际仍在运行时，即使租约已过期也拒绝放行。
- 控制面重启：读取原子替换的状态文件，核对并终止遗留容器；仅恢复未领取、原绝对期限未过且源码归档仍合法的队列请求，不重放已运行任务。
- 控制面消失：容器 PID 1 的限时进程终止后容器结束；停止的容器元数据由下次核对清理。
- 重跑只换机器：判据是该 Worker 出现过 attempt，**不按 `outcome` 过滤** —— 控制面在容器仍运行时崩溃会留下 `outcome: null`，那台机器同样执行过本次任务。重跑不增加额度，也不会回到旧机器。
- 客户端断线：任务仍由控制面管理，可以用任务 ID 重新查看日志和结果。

任务结果和源码归档存储在控制面本地磁盘，任务记录同时保存源码归档摘要。配置远端副本后，每个状态转换先写本地提交回执，再向不同物理故障域推送内容寻址归档，至少取得一台远端确认后才发布本地终态。quorum 2 表示本地加任意一台远端；配置两台远端时，任意一台远端故障仍可继续提交。恢复方会核对任务元数据、源码摘要和远端提交证明，冲突或不可读的新版本一律失败关闭。

远端副本只保护已确认的任务状态、源码、日志、事件和声明产物。运行中的进程、内存和尚未检查点的实时输出不会迁移。控制面也不会自动在另一台机器监听同一 SSH 地址：M3 丢失后，运维必须先用独立保存的配置、token 和 SSH 凭据重建控制器，并确保旧控制器已停止。完整故障矩阵见 [failure-modes.md](failure-modes.md)。

任务状态复制不保护 PostgreSQL、Redis、业务容器的可变目录或数据库事务。它们需要各自的备份、复制、写入隔离和故障注入验收；Ceph 健康、容器自动重启或任务元数据副本都不能替代这些工作。

节点可由管理员在线启停。切换和任务分配共用调度锁，配置先原子落盘再更新内存状态；已有活动任务的节点不能禁用。探测与状态接口读取同一份运行时节点视图，因此无需重启控制面。

## 信任和隔离

这是面向同一拥有者设备的单用户计算池。配置、token、SSH 运维账号和容器运行时属于可信控制边界；持有 token 的人可以请求资源范围内的构建。任务进程没有 Docker socket，也没有控制面的 SSH 凭据。

控制面默认只监听宿主回环的明文 HTTP。跨不可信网络时由 `src/tls.rs` 用 rustls 终止 TLS，客户端必须校验服务端证书（系统信任链或显式 `--ca-file`，没有跳过校验的开关）。需要把控制面借给工作台或临时脚本时，用 `src/credentials.rs` 签发短期凭据：磁盘只存 SHA-256 摘要，到期是半开区间，撤销后下一次请求即被拒绝。凭据库损坏时动态凭据一律拒绝，但根 token 仍然可用 —— 一个坏文件不该把运维锁在控制面之外。当前凭据只解决"可撤销"，不做按主体的权限分级。

`src/access.rs` + `src/api.rs::audit_access` 给每个请求留一行审计到 `home/access.jsonl`：主体、身份来源、凭据 id、决定与理由、方法、路由模板、任务 id、状态码。鉴权与留痕在同一个中间件里完成，处理器只拿 `Principal`，所以不存在"某个接口忘了记"。日志故意不含 token、请求正文和查询串，未命中路由只记 `unmatched` 而不记原始路径。文件按 4 MiB × 3 代滚动（上限 12 MiB），中间行损坏 fail-closed，只有当前文件末尾的崩溃半行被容忍并在下一次写入前切掉；审计不可写时副作用请求直接 503，不做没有记录的动作。

`src/metrics.rs` 把控制面已有的结构化事实渲染成 Prometheus 文本：终态任务按 `phase` + `exit_code` 分成 6 类（成功、三种失败结构、取消、中断），排队与执行时长是累计桶直方图，另有尝试/重试计数、队列深度与最老等待、清理未确认数、节点资源水位，以及访问审计各代字节数。失败分类不解析 `job.message`，所以改文案不会改变语义；节点探测失败时资源报 0 而不是沿用旧快照，避免把陈旧数字读成当前水位。

指标走独立的 `metrics_listen`（默认关闭，启动行打印 `metrics=off` 或实际地址），不挂在 `/v1/...` 上：Prometheus 默认 15 秒抓一次，走控制面路由会经 `audit_access` 在几分钟内冲掉 12 MiB 的有界审计。抓取只读 `health_snapshot` 缓存，不触发远端探测；端点无鉴权，因此只暴露节点名与数值。

Docker 容器共享内核，不能用此原型承诺对恶意租户的强隔离。公司重要主机建议使用专用计算 VM 或 rootless Docker，并持续更新运行时。宿主业务的突发负载仍可能影响任务，需要实测预留量。

工作台用户本身能编辑自己的工作台文件；任务容器只能看到显式提交的源码。两种权限不要混淆。构建时不要让源码同步工具并发更改项目文件。

## 对开源方案的取舍

- **OpenSSH**：承担完整 SSH 兼容性。Rust 只进行字节透传和节点命令编排。
- **Lima**：可选的 Mac Linux 工作台，关闭宿主目录共享；任何稳定 Linux/OpenSSH 后端也可替代。
- **Docker / Linux cgroups**：承担进程、资源和文件系统隔离。使用非 root、只读系统层、禁网与 tmpfs。
- **Slurm**：借鉴其资源预约和作业状态模型；首版没有引入集群身份数据库与守护进程部署。
- **sccache / Icecream**：后续适配编译单元调度与缓存。当前只分发整个命令，不能标成已集成这两者。
- **OpenSSI / Kerrighed / Popcorn**：记录为研究路线，不把实验内核混入公司主机，也不声称已有分布式共享内存。

## 后续工作

优先增加按主体的权限分级（当前短期凭据与根 token 权限相同；访问审计已可查询但只记录不约束，指标端点无鉴权）、可配置输出导入策略、内容寻址输入缓存、sccache adapter、原生 macOS VM Worker，以及容器引擎内部资源探测。阶段事件已可按任务 ID 查询，指标已在独立端口上提供抓取；有限持久队列不等于控制面多实例高可用，服务多实例调度和真正的 SSI 属于独立能力，需要独立验收。
